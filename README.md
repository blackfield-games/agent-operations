# Blackfield — Agent Operations

**Combined-arms tactical combat with a living, operator-rendered frontier.**

Blackfield pairs hand-tuned competitive arenas with an ambient open world rendered by a distributed network of operators. The project is built on Unreal Engine 5 (Lyra), and its compute economy settles on Base.

Website: [blackfield.games](https://blackfield.games)

## Architecture

Three loosely coupled backends sit behind the game client, and the arena makes the game itself playable by agents.

### Arena

The agent-native PvP layer. Blackfield is one combat core playable by humans and autonomous agents on equal footing: a human drives a pawn through a controller, an agent drives an identical pawn over the **Agent Gateway** — a server-authoritative observation/action protocol whose wire types live in `arena/proto`. The protocol is the contract two implementations share: a headless, deterministic Rust reference arena — CI-testable, replayable, and the agent-vs-agent benchmark — and, later, the Unreal Engine dedicated server, so an agent written once plays both unchanged. Three invariants are encoded in the types rather than left to a server's goodwill: an observation carries the seat's own state plus only the entities it could perceive that tick, with no field for full world state, so an omniscient agent cannot be built on the protocol; every action is an explicit request the server validates and clamps through the same rules a human's input goes through, never trusted as state; and all spatial quantities are integer fixed-point, so a match replays bit-for-bit and commits to a single canonical hash for on-chain attestation and reproducible grading. Every message carries the protocol version, checked at the handshake, so the reference arena and the engine cannot silently diverge as they evolve. The matchmaking modes — Human, Agent, and Mixed — are simply which controller kinds fill the seats.

The reference arena lives in `arena/core`: a fixed-tick, server-authoritative match loop that puts every seat's action through one validate-and-clamp gate — the same path a human's input would take, rejecting a wrong-version, wrong-match, wrong-seat, or stale-tick envelope and clamping move speed so no envelope buys god-mode — then advances integer combat — instant beam-hitscan by default, or an optional traveling-projectile mode whose shots fly across ticks and can be dodged, with friendly fire an opt-in rule (off by default) that puts a team's own line of fire at risk — and scoring to a win condition and emits each seat's parity-bounded observation. A seat that misses its action simply forfeits the tick, so a slow or hung agent never stalls the match. Every simulated tick's accepted actions are recorded as a replay that re-runs the match bit-for-bit from the seed, so an agent-vs-agent match plays end to end — and is graded and committed to a single canonical hash — in CI today, with no engine dependency. A finished match is sealed into a self-determining record — the seed and action stream bundled with the arena bounds, the combat tuning, and the result they produced — that any third party re-runs and checks from the record *alone*: it either reproduces the exact outcome and the canonical hash or rejects the record with a typed error, never panicking on a truncated or tampered one, so an on-chain settlement check and a spectator/replay feed can both trust a match they did not run.

An agent becomes a player through the Python SDK in `agents/arena_client`: it speaks the Gateway directly — a version-checked handshake that refuses a protocol skew before a match starts, a parity-bounded observation in, a validated action out within the tick's deadline — and treats a server rejection or a missed deadline as a normal outcome (forfeit the tick, read the next observation as ground truth) rather than desyncing, so a slow or rejected agent degrades gracefully instead of hanging the match. A deterministic scripted baseline agent ships with it, and a loopback harness (`arena/harness`) drives the real reference core over a line-delimited JSON transport, so a full baseline-vs-baseline match plays through the SDK against the actual simulation and produces a decisive, reproducible result today — the same agent code will later connect to the Unreal dedicated server unchanged.

Which seats a match puts on the same battlefield is a matchmaking concern, not a code fork: the matchmaker in `arena/match` forms matches over that one reference core from per-mode waiting queues, where the mode decides which controller kinds may fill the seats and what composition is valid — `Human` is human-only, `Agent` is agent-only ranked A2A, and `Mixed` puts at least one human and at least one agent on the same battlefield, the headline cross-play case, and can never form all-one-kind. A ranked agent seat must present an identity token — the on-chain agent address proven by the join signature — that is verified *before* the seat is queued, so an unauthenticated or duplicate agent can never reach a settle-able ranked match; the verifier is a stub for the on-chain agent registry today but enforces the same accept/reject boundary, so the gate is real rather than deferred. The per-mode queues share one lock, so a join that completes a match selects and removes its whole roster atomically — concurrent joins can neither double-seat a participant nor start a match a seat short — and the formed match is seeded from its own minted id, so it is reproducible from that id alone, and plays under its configured arena's static geometry — the vision blockers and world pickups the core simulates and commits to the replay hash — loaded from a per-arena map at formation (the default arena is empty, so a match left unconfigured is byte-identical to before). A match can also be watched: a read-only spectator feed projects a broadcast view of the whole battlefield — every pawn's public on-stage state (position, team, health, score), a distinct projection from any seat's parity-bounded observation and deliberately carrying no private HUD internals — and fans it to many spectators decoupled from the simulation, where a slow consumer's frames are dropped rather than allowed to stall the tick loop and a spectator has no channel to inject an action; the same broadcast frames re-run from a finished record drive replay playback, so a third party can watch an agent-vs-agent match live or after the fact without ever influencing it.

### Mesh

A distributed render pool. The coordinator service (Rust, Axum) queues render jobs and dispatches them to earner clients over WebSocket or HTTP polling. Jobs enter the queue at runtime through a `POST /jobs` ingestion endpoint — the seam the agents pipeline uses to turn a scene patch into a render job — which validates every field of the request (a non-zero, bounded deadline, a payout that parses as bounded wei, a size-capped inputs blob, and an optional `buyer` that — when present — must be a well-formed EVM address, so the validated compute can be metered to it) and mints the job id server-side, so an untrusted caller can neither overwrite an existing job nor inject a value that crashes `/stats` later, before the spec is persisted `queued`. When an ingest token is configured (`--ingest-token` / `COORDINATOR_INGEST_TOKEN`), `POST /jobs` additionally requires an `Authorization: Bearer <token>` header — compared in constant time, with any absent, malformed, or wrong value rejected `401` — so only the authorized world-gen pipeline can enqueue payable work; left unset the endpoint stays open for local development and the coordinator logs a startup warning. The queued backlog is bounded by `--max-queued-jobs` / `COORDINATOR_MAX_QUEUED_JOBS` (default 10000): a create that would exceed the cap is shed with a retryable `503` rather than growing the queue without bound, while the boot-time seed and crash-recovery requeue are exempt. Registration attempts are rate-limited per source IP — a token bucket (`--max-registrations` / `COORDINATOR_MAX_REGISTRATIONS`, default 4096/min) checked before the secp256k1 signature recovery, so a flood of registrations is shed with `429` on HTTP `/register` or a closed socket on the WebSocket Hello before any curve work, and the bucket map is itself bounded so the limiter cannot be turned into the memory exhaustion it defends against. The source is the connection peer IP by default; behind a reverse proxy that is the proxy's address, so when the peer is a configured trusted proxy (`--trusted-proxies` / `COORDINATOR_TRUSTED_PROXIES`, empty by default — forwarded headers are ignored unless the connecting proxy is listed; entries are exact IPs or CIDR ranges, e.g. `10.0.0.0/8,2001:db8::/32`, so one range can cover a proxy fleet, and a malformed entry is rejected at startup) the coordinator instead keys on the real client recovered from the rightmost forwarded hop that is not itself trusted — the address the trust boundary actually observed — attributing distinct clients behind one proxy to distinct buckets, while an untrusted peer's forwarded headers are ignored so a direct caller cannot spoof a forged source. Both the standardized RFC-7239 `Forwarded` header (the `for=` element — quoted values, bracketed IPv6, and obfuscated/`unknown` tokens are all handled) and the legacy `X-Forwarded-For` are understood, with `X-Forwarded-For` taking precedence when both are present — the no-regression order, since before `Forwarded` was parsed an XFF-fronted deployment already ignored any client-supplied `Forwarded`, so an attacker behind such a proxy cannot inject one to override the real XFF-attributed client; `Forwarded` is consulted only when no `X-Forwarded-For` is present at all, so a proxy that emits *only* `Forwarded` must itself strip or overwrite any inbound `X-Forwarded-For` (the same discipline XFF has always required of a trusted proxy). Both registration paths resolve the source identically. This in-process limiter is a backstop: edge/OS per-source rate limiting — proxy/CDN per-IP request limits, kernel SYN/connection shaping, IPv6 prefix-level shaping — remains the primary flood defense. An established earner session is held only while it stays responsive: the coordinator pings idle sessions and closes one that sends no frame — not even a keepalive pong — within a read-idle deadline (`--session-idle-timeout-secs` / `COORDINATOR_SESSION_IDLE_TIMEOUT_SECS`, default 90s), so a half-open or vanished peer (a pulled cable) is reclaimed within the bound rather than parking a connection until the ~2h OS TCP keepalive, while a live earner — even idle between jobs — auto-pongs and is never dropped, and an in-flight render's heartbeats keep its session alive the same way. Each earner registers its available GPU and the job types it can handle — proving control of its secp256k1 session key by signing the registration (over a single-use challenge the coordinator issues on each WebSocket connection, so a captured registration can't be replayed), so a client can only register an identity it holds the key for — and signs every result with that same key; the coordinator verifies both signatures and checks the result is well-formed — a 256-bit output hash, a fetchable artifact URL, and a render time that is non-zero and plausible for the job's deadline — before accepting it, then records a pending EAS render receipt for each validated job. A background relayer drains that backlog, claiming a gas-bounded batch of pending receipts (`--relay-batch-size` / `COORDINATOR_RELAY_BATCH_SIZE`, default 32) and submitting it to the `RenderReceipts` contract in one `issueReceipts` (`multiAttest`) call, then marking each row with its submission-order attestation UID so the backlog clears as receipts are published; because that batch is atomic — one receipt already on-chain, or one the contract rejects, reverts the whole call — a revert falls back to per-receipt submission so the offending receipt is isolated — an already-on-chain one is marked, and one that hits a non-retryable on-chain error (e.g. a receipt naming a region whose render fee the coordinator cannot cover) is dead-lettered: quarantined and surfaced at `/stats` rather than dropped or hot-looped, so one poison receipt never blocks the rest — while the rest still drain, and a whole-batch revert from a global misconfiguration (an unauthorized coordinator signer) still stops the drain loudly rather than quarantining every receipt. A dead-lettered receipt is never auto-re-claimed, but once its cause is fixed (the coordinator funds the region fee, or the operator authorizes the signer via `setCoordinator`) an authenticated operator can enumerate the stuck receipts through `GET /receipts/dead-lettered` (oldest-first, bounded, with a `total`/`truncated` signal) and re-arm one for the next drain through `POST /receipts/{id}/redrive` — or, after a broad cause is fixed, re-arm every quarantined receipt in one call through `POST /receipts/redrive-all` (returning the `rearmed` count) — all gated by the same bearer token as `POST /jobs`, re-attempting each receipt exactly once and re-dead-lettering it if it still fails, with the off-chain `dead_lettered_at IS NULL AND uid IS NULL` re-arm guard plus the on-chain `DuplicateReceipt` jobId fence keeping a re-driven receipt that actually landed from double-attesting. Alongside the receipt, when compute metering is enabled (`--compute-rate-wei` / `COORDINATOR_COMPUTE_RATE_WEI`, default `0` = off, opt-in) and the job carries a buyer, the coordinator records a pending `ComputeMeter` debit — `rate × render-seconds` in wei, the metering twin of the receipt — in the same settle transaction, so a crash before the on-chain `spend` cannot lose the charge. A debit relayer drains that backlog the same way the attestation relayer drains receipts — submitting each pending debit as a `ComputeMeter.spendOnce` (the idempotent entry point, fenced per `jobId` so a crash-retried debit reverts rather than double-charging) and marking it once it lands, and dead-lettering any debit that hits a non-retryable on-chain error (an underfunded buyer's `InsufficientCredit`) — quarantined and surfaced rather than dropped or hot-looped, so one poison charge never blocks the rest of the backlog; a dead-lettered debit is never auto-retried, but once its cause is resolved (e.g. the buyer tops up) an authenticated operator can enumerate the stuck charges through `GET /debits/dead-lettered` (oldest-first, bounded, with a `total`/`truncated` signal) and re-arm one for the next drain through `POST /debits/{id}/redrive` — or, after a broad cause is fixed (the spender re-authorized via `setSpender`, or a class of underfunded buyers tops up), re-arm every stuck charge in one call through `POST /debits/redrive-all` (returning the `rearmed` count) — all gated by the same bearer token as `POST /jobs`, which re-attempts each charge exactly once and re-dead-letters it if it still fails — with the live Base spender operator-gated on a Base RPC and an authorized spender key; an unmetered or buyerless job still settles and is still attested, accruing no debit. The job queue, results, pending receipts, and pending debits persist in SQLite, so an interrupted coordinator reclaims in-flight work on restart rather than dropping it. Shared wire types live in `proto`. Connected GPUs, queue depth, both the attestation and debit backlogs (each including its dead-letter depth and the age of its oldest stuck row, so an operator can alarm on how long owed proof or charges have been quarantined, not just that some are), and the mean progress across in-flight jobs — a working-vs-wedged signal aggregated from the latest `progress_pct` each earner reports on its heartbeats, reset to 0 per dispatch so it reflects only the work running now, and read alongside the oldest in-flight age that surfaces a lone stuck job the mean would dilute — are exposed at `/stats`.

### Contracts

A Foundry project targeting Base.

- **ComputeMeter** converts $BLCKFLD into per-buyer compute credit, debited as validated jobs complete.
- **RegionAuthority** mints a region NFT against a $BLCKFLD stake; fees earned within a region — including artifact mint royalties and validated render fees — are deposited on-chain and claimed by the current holder, with accrued fees settled to the outgoing holder on transfer.
- **RenderReceipts** publishes each validated render's attestation to the Ethereum Attestation Service, and lets an authorized coordinator revoke the receipt for a render later found invalid, withdrawing the on-chain attestation and excluding it from the live receipt counts. Each validated receipt also routes a configurable real-$BLCKFLD fee-share — scaled by the render's seconds and paid by the issuing coordinator — into the receipt's region fee pool on `RegionAuthority`; a region with no staked holder simply skips the fee so the attestation is never blocked. A coordinator settling many validated jobs at once can issue them in a single transaction — one EAS `multiAttest` over the batch — applying the same per-job duplicate fence, live counters, and region fee route to every element atomically: a batch carrying an already-issued or intra-batch-duplicate job, or an element whose region fee the coordinator cannot cover, reverts as a whole rather than leaving any job attested-but-unpaid.
- **ArtifactTemplate** mints player-authored equipment and structure templates as ERC-1155 tokens; each mint debits a rarity-scaled $BLCKFLD fee from the recipient's `ComputeMeter` credit and routes a separate rarity-scaled $BLCKFLD royalty into the minted artifact's region fee pool on `RegionAuthority`. A template may declare an optional max supply at registration (0 = unlimited), capping how many units can ever be minted so a high-rarity tier can be made genuinely scarce.
- **AgentRegistry** is the on-chain identity for an autonomous agent: an identity is keyed by the registrant's own key (never a victim address) against an optional $BLCKFLD bond, and ranked reputation — written only by the settlement contract — persists across deregistration, so a loss can't be laundered by re-registering.
- **MatchSettlement** escrows an optional two-sided $BLCKFLD wager for an agent-vs-agent ranked match: an authorized result attester opens the match and either names the decisive winner (who takes the pot) or a draw (both refunded), commits the arena replay digest on-chain, and writes ±reputation back to `AgentRegistry`. The reputation magnitude is a fixed owner-set amount by default; once the owner sets a cap, the attester may instead supply a per-match skill-scaled delta — the off-chain Elo result, where a favoured win moves standing less than an upset and a draw can move it down — which the contract bounds by that cap and applies zero-sum (`+d` to one agent, `−d` to the other), never beyond the ceiling. A multi-seat (FFA / 3+) ranked result settles reputation through `settleField`, which records a zero-sum per-seat delta vector (the N-seat generalization of the Elo result) to every seat at once — the deltas must sum to exactly zero and each stay within the cap, and the field reuses the same idempotency fence so a match settles once; this `settleField` path is reputation-only. The N-seat **wager** is a parallel escrow — `openFieldMatch` stakes a 2..64 roster where each agent funds its own seat into a single funded bitmap — sharing that one idempotency fence, so a matchId is at most one record across the 1v1, field-settle, and field-wager paths. Once every seat is funded, `settleFieldWager` distributes that pot by placement — the attester supplies a per-seat payout split the contract enforces to sum to exactly the pot (the off-chain placement curve, bounded on-chain just like the reputation vector) and writes the zero-sum per-seat reputation in the same atomic, fenced call; an underfunded field is never partly paid, only recovered by cancel/refund. Each agent funds its own seat and can reclaim it until a peer funds; if the attester then never resolves a fully-funded match — 1v1 or field — the escrow can be self-refunded once an owner-set deadline passes (returning every funded seat), so a vanished attester can never strand the stakes.

### Agents

The world-generation pipeline. A LangGraph supervisor routes a world brief through eight specialist stages: director, terrain, biome, prop, lighting, NPC, optimization, and validation. Each stage writes its own OpenUSD layer, which `compose` then sublayers into a single `world.usda` in a fixed strength order. When validation fails, the supervisor can return the brief to the earliest failing stage for revision. Each stage runs as a Temporal activity, so an individual step can fail and resume without restarting the pipeline.

These pieces connect end to end: the agents author scene patches, which become render jobs; the mesh dispatches those jobs to earners, who render and cryptographically sign the output; and validated work is metered by `ComputeMeter` and attested by `RenderReceipts` on Base.

## Building and Testing

Each backend builds and tests independently.

**Arena** — Rust workspace (`proto`, the Agent Gateway protocol; `core`, the headless reference match sim; `match`, the matchmaker that forms Human/Agent/Mixed matches over that core; `harness`, the loopback gateway the agent SDK plays against). The Python agent SDK lives in `agents/arena_client` and is exercised by the agents test suite:

```
cd arena
cargo test
```

**Mesh** — Rust workspace (`proto`, `coordinator`, `earner`):

```
cd mesh
cargo test
cargo run -p coordinator   # serves 127.0.0.1:8787
```

**Contracts** — Foundry (dependencies vendored under `contracts/lib`):

```
cd contracts
forge test
```

**Agents** — Python (dependencies in `pyproject.toml`):

```
cd agents
python -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/python -m pytest
```
